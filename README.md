# RGB-D Fusion for 6D Object Pose Estimation on YCB-Video

<img width="456" height="644" alt="successes" src="https://github.com/user-attachments/assets/4704157a-1578-4e91-ab72-fc8872a2696c" />

Given a single RGB-D frame and a segmentation of a known object, this project predicts the rigid transform (rotation R in SO(3) and translation t in R^3) that maps the object's CAD model into the camera frame. Reliable 6D pose is the prerequisite for robotic grasping, bin picking, and augmented reality, where a system has to know not just where an object is but how it is oriented.

The model fuses a ResNet-18 appearance encoder with a PointNet geometry encoder and is compared against an RGB-only baseline on the BOP release of YCB-Video. Evaluation follows the official BOP'19 protocol.

| Model | ADD-S AUC | ADD(-S) AUC | ADD-S < 2 cm (%) | ADD(-S) < 0.1d (%) |
|---|---|---|---|---|
| Baseline (RGB) | 80.6 | 69.9 | 68.6 | 44.6 |
| Final (RGB-D) | **92.6** | **88.5** | **98.1** | **87.3** |

Scored once on the 2,024 held-out BOP'19 test targets across 10 objects, after all tuning was frozen.

## What the model does

There are three input streams:

1. **Appearance.** An ImageNet-pretrained ResNet-18 with its classifier removed maps the masked 224x224 RGB crop to a 512-d feature.
2. **Geometry.** A PointNet backbone (five shared 1x1 convolutions, 3 -> 64 -> 64 -> 64 -> 128 -> 1024, each with batch norm and ReLU, then a global max-pool) maps the centred 1000-point cloud to a 1024-d feature.
3. **Class.** A 16-d learned embedding of the object index.

The concatenated 1552-d vector goes through an MLP head (1552 -> 512 -> 512 -> 9) producing nine outputs. The first three are a translation residual added back to the point cloud centroid, so the network only refines an estimate that is already metric. The last six are the continuous 6D rotation representation of Zhou et al., orthogonalised into a rotation matrix by Gram-Schmidt. The whole thing is roughly 12.4M parameters.

The loss is `SmoothL1(t, t_gt; beta=0.01) + 0.5 * L_rot`, where `L_rot` is a symmetry-aware chordal loss: the squared Frobenius distance from the predicted rotation to the *nearest* rotation in the set of ground truths generated by the object's BOP symmetry annotations, with continuous symmetries discretised into 36 steps. Without it, a symmetric object gets penalised for predicting a visually identical pose, which puts a floor under the rotation loss that no amount of training removes.

The baseline is the same ResNet-18 and class embedding with no depth at all. In place of a point cloud it receives a 3-vector of crop geometry (the viewing ray of the crop centre and a log scale term) and decodes translation from a clamped log-depth. It exists to isolate one question: what does metric depth actually buy?

## Setup

Python 3.10 or newer, plus:

```bash
pip install torch torchvision numpy scipy pillow imageio wandb
```

Training logs to wandb, so run `wandb login` first. The entity and project are set inside `train.py` and will need changing to your own.

### Data

Download the YCB-V files from the [BOP website](https://bop.felk.cvut.cz/datasets/) and arrange them like this:

```
data/
  train_real/                              real training scenes
  train_pbr/                               synthetic PBR scenes
  ycbv_test_all/test/                      test scenes
  ycbv_base/ycbv/test_targets_bop19.json   the official test target list
  ycbv_models/models_eval/                 subsampled meshes and models_info.json
  models/                                  checkpoints get written here
```

The first run parses every scene's JSON and caches the sample index to `data/<split>.pkl`. That pass is slow and reads a lot of depth images, but it only happens once. Delete the pickle if you change the filtering rules.

### Training

```bash
python run.py
```

The hyperparameters are set in `run.py` (20 epochs, batch size 128, learning rate 2e-4). Swap `PoseEstimator`/`train_model` for `Baseline`/`train_baseline` in that file to train the RGB-only variant instead. The checkpoint with the best validation loss is saved automatically.

### Evaluation

```bash
python eval.py data/models/best_ne_20_bs_128_lr_0.0002.pt --variant rgbd
python eval.py data/models/best_baseline_ne_10_bs_128_lr_0.0002.pt --variant baseline
python eval.py <checkpoint> --variant rgbd --json results.json
```

This prints ADD-S AUC, ADD(-S) AUC, ADD-S below 2 cm, and ADD(-S) below 10% of object diameter, overall and per object.

## Data handling

**Objects.** Ten of the 21 YCB-V objects (BOP ids 1 to 19, odd), covering boxes, cans, a bowl, a pitcher, a drill, scissors, and a clamp. Three of them (master chef can, bowl, large clamp) are marked symmetric by BOP.

**Filtering.** A training sample survives only if its visible fraction is at least 0.1 and at least 10 pixels carry valid depth inside the visible mask. This removes crops that are degenerate rather than merely hard. After filtering there are roughly 400,000 training crops and 50,000 validation crops.

**Depth branch.** Depth is masked by the visible mask, back-projected through the camera intrinsics into a point cloud, subsampled without replacement to 1,000 points, converted to metres, and centred by subtracting its centroid. The centroid is kept and passed to the decoder, since that is what the predicted translation is a residual against.

**Augmentation (RGB-D model, training only).** Crop jitter of plus or minus 10% in scale and centre, random mask dilation, colour jitter, and random erasing on the image side. Point dropout (each cloud drawn from 30 to 100% of available points, then refilled with repeats) and 5 mm Gaussian noise on the cloud side.

**Splits.** By scene, never by frame. Consecutive video frames are close to identical, so a random frame split leaks the test set into training and inflates every number in the table above. Scenes 0-47 and 60-75 train, 76-91 validate, and the 12 BOP test scenes (48-59) are held out entirely. Validation and test use seeded, deterministic point sampling, otherwise the metric being compared across epochs moves on its own.

## What the results say

**Depth is worth more as a parametrisation than as a feature.** The largest single gain comes from predicting translation as a residual off the point cloud centroid rather than regressing depth from scratch. The network starts from an estimate that is already metric, and the 2 cm success rate jumps by 30 points. The baseline has to infer depth from crop scale alone, which is exactly where it falls apart.

**The remaining errors are rotational and structured.** Two failure modes account for most of what is left. The first is occlusion: the potted meat can reaches only 50.9% below 0.1d, and the single worst test sample is a can 42% visible behind a sugar box. The second is face confusion on near-symmetric shapes, where a box's pose flips between two visually similar faces. Scissors are their own case, at 20.0% below 0.1d but 91.2 ADD-S AUC, meaning the strict threshold rather than gross failure drives the low number. The training curves agree from a different direction. At the selected checkpoint the translation loss is effectively identical on train and validation (0.0029 against 0.0029), while the rotation loss is four times higher on validation (0.028 against 0.112). Translation generalises, rotation overfits.

**The loss has to match the geometry.** Penalising raw rotation error on symmetric objects puts a floor under the loss that no amount of training gets past, and the symmetry-aware chordal loss removes it.

## Limitations

The model consumes ground-truth masks and bounding boxes at test time, so the point cloud is the object's actual visible surface and its centroid is already close to the answer. Methods like PoseCNN and DenseFusion run on predicted segmentation, so the numbers here are not directly comparable to theirs.

The RGB baseline is not a clean ablation. It differs from the final model in more than depth: it trains for 10 epochs instead of 20, uses Adam instead of AdamW with weight decay, and sees none of the augmentation. Depth is almost certainly the dominant factor given the size of the gap, but the comparison as it stands does not prove that on its own.

There are no ablations for the symmetry-aware loss or the augmentation pipeline. Both are claimed to help based on training behaviour rather than a measured held-out delta.
